# 🧭 PI 情报 · PI Intelligence

面向 **miRNA 生物发生 / TDMD / 代谢** 方向的 PI 地图:谁在做什么、跟我撞不撞车、
有没有互补的方法能力、方向这几年在往哪儿漂。

**站点:** https://zouxdsheldon.github.io/pi-intel/
**姊妹站:** https://zouxdsheldon.github.io/pi-grants/ (基金 + 文献 + 写作,语料上游)

---

## 一句话说清它做了什么

从姊妹站已有的 **1093 篇**方向文献语料里,把**末位作者**聚成 PI 候选(950 位),
按同名风险分级,只对**可归属到个人**的名字去 Europe PMC 抓作品集(48 位 / 654 篇),
然后用**跟论文卡片同一把尺**的打分器算出每位 PI 的方向指纹、年度轨迹,
以及跟你的三项关系指标。

**不用 Google Scholar**(无官方 API)、**不用 JCR 影响因子**(版权数据)、
**不调用任何大语言模型**。页面上每个数字都能从 `data/pis.json` 里手工复算出来。

## 算法

### 1. PI 抽取(`scripts/pi_extract.py`)

| 步骤 | 做法 |
|---|---|
| 候选生成 | 按**末位作者**聚合语料记录;同时保留「任意位置」计数 |
| 姓名归一 | 语料里有两种作者名格式,统一成 `姓\|名缩写` 键 |
| 单位解析 | 按分隔符切段 + 机构关键词过滤 + 地址/科室段拒绝 |
| 地区归属 | 单位串里的国家/地区词 |

> ⚠️ **末位作者 = 通讯作者是惯例,不是事实。** 合作论文、共同通讯、
> 部分领域的字母序署名都会让这个代理指标出错。页面上如实标注为「末位作者」。

### 2. 同名风险分级(核心难点)

Europe PMC **没有作者唯一标识**(不是 ORCID 数据库),`Zhang X` 在全库有
**十几万**篇文章 —— 那不是一个人的作品集,是几百个人的。分级用四个独立信号:

- 姓氏在语料中对应的**名缩写种类数**(种类越多越可能撞名)
- 名缩写**字母数**(单字母 `X` 远比 `MV` 危险)
- 姓氏是否属于高频姓氏集合
- Europe PMC **全库命中数 vs 领域内命中数**的比值

分级结果:**低 224 / 中 454 / 高 272**。榜单**只收低风险**的名字,
中高风险的**全部单列**在「⚠️ 同名排除名单」页并注明排除原因 —— 藏起来才是不诚实。

### 3. 合作者锚定(同名消歧的可计算手段)

一条抓回来的记录,若其作者表里出现**语料中已知的合作者**,就标记为「已锚定」。
未锚定的记录**保留但标注**,不删除。

> **这里踩过一个坑,值得写下来。** 第一版拿**全部**合作者做锚点,
> 结果 `Wang Y` 的锚定率(58%)反而高过 `Bartel DP`(24%)。
> 原因是常见姓名的合作者也是常见姓名,到处都能匹配上 —— 锚定的是**姓名串**而不是人。
> 改成只用「**可区分合作者**」(姓氏在语料中缩写种类 < 6、且名缩写 ≥ 2 字母)之后,
> 那些本来就锚不上的名字锚定池直接归零 —— 这才是正确行为。
>
> 因此:**未锚定 ≠ 不是本人**,只是没有独立证据;
> **锚定率低 ≠ 数据差**,资深 PI 若语料只收了他几篇,已知合作者本来就少。
> 当前 48 位里 **38 位**有锚定证据。

### 4. 抓取(`scripts/fetch_pis.py`)

Europe PMC REST,查询带**领域限定子句**(否则常见姓名会返回整个医学库)。
线程池 + 全局墙钟预算 + 重试;超预算写出已抓部分而不是失败退出。
**只写自己的输出文件,绝不回写语料**(单写者原则)。

排序不用发文量 —— 那等于保证榜单头部全是无法归属的名字;
改成**先按风险分层,层内按资历排**。

### 5. 方向指纹与轨迹(`scripts/analyze_pis.py`)

复用姊妹站的 `_scoring.py` / `_methods.py`,所以 PI 的方向分和论文卡片的分
**在同一把尺上**,可以直接比。

- **指纹** = 8 个方向上的**近年加权**得分向量(近三年权重更高)
- **轨迹** = 逐年方向占比
- **漂移角** = 近 3 年向量 vs 前 3 年向量的夹角(样本不足则不算,不显示 0°)

### 6. 三项关系指标

| 指标 | 算法 | 护栏 |
|---|---|---|
| **竞争度** | PI 指纹与你的方向权重向量的**余弦** | — |
| **互补度** | 稀缺方法数 / 检出方法数 | 检出方法 **< 4** 个 → **不可测**(不是 0) |
| **合作可能** | 互补度 × 竞争惩罚,竞争度 > 0.55 起线性压分、> 0.90 归零 | 互补度不可测时**一并不可测** |

> **两个被审计出来的缺陷,已修。** 其一:只检出 1 个方法时互补度算出满分 1.0 ——
> 那是**没测到**,不是高度互补,现在返回「不可测」。
> 其二:稀缺阈值原本固定 5%,而语料里几乎所有方法词的占比都低于 5%,
> 这让「稀缺」这个概念变得空洞;现在取**语料方法词频的中位数**(当前 0.00366),
> 阈值随语料自适应。
>
> 48 位里只有 **25 位**方法样本够算互补度,象限图会**明确报出**被略过的位数。

## 页面

| 页 | 内容 |
|---|---|
| 🏆 PI 榜单 | 卡片:方向指纹条 + 三项指标 + 四个折叠证据抽屉(指标怎么来的 / 代表作 / 同名风险与锚定 / 与旗舰方向撞车检查)。筛选:搜索、方向、地区、排序、仅看有锚定、仅看可测 |
| 🎯 竞争-互补象限 | 内联 SVG。点面积 = 作品集篇数;**实心** = 有锚定证据,**虚线空心** = 无锚定证据 |
| 📈 方向轨迹 | 逐年方向占比堆叠面积图 + 漂移角 |
| ⚖️ 两人对比 | 并排指纹/指标/方法差集 + 与我的方向重叠 |
| ⚠️ 同名排除名单 | 60 条被排除的高发文量候选 + 逐条排除原因 |
| 📐 方法与局限 | 算法全文 + 三条踩过的坑 + 局限清单 |

导出 CSV(遵循当前筛选,18 列含风险说明与锚定计数);
每位 PI 可写合作/竞争备注,**存本机浏览器,不上传**。

## 已知局限(页面上也写着)

1. **Europe PMC 无作者唯一标识。** 这是整个站最大的不确定性来源,锚定只是缓解不是解决。
2. **单位只有第一作者的**,末位作者的单位常常缺失,靠推断。
3. **方法能力靠词表匹配摘要**,做了但没在摘要里写的方法测不到 —— 所以「不可测」很常见,而且是诚实的。
4. **期刊层级是代理指标**,不是科学质量。
5. **语料本身有取向**(围绕你的 8 个方向抓的),所以这是**方向内的地图,不是全领域名录**。资深 PI 在语料里可能只有几篇。
6. **竞争度衡量的是「写得像」**,不是「在抢同一个课题」。真正的撞车要看抽屉里的撞车检查和代表作。
7. **末位作者 ≠ 通讯作者**(见上)。

## 本地跑

```bash
python3 scripts/pi_extract.py                 # 语料层:候选 + 风险分级(不联网)
python3 scripts/fetch_pis.py --limit 90       # 抓作品集(Europe PMC)
python3 scripts/analyze_pis.py                # 指纹 / 轨迹 / 三项指标
python3 tests/run_ui_tests.py                 # 前端行为测试
python3 -m http.server 8000                   # 然后开 http://localhost:8000
```

## 测试

`tests/run_ui_tests.py` 把 `index.html` 的脚本块抽出来,喂给一个极简 DOM 桩,
用 **全部 48 位真实 PI** 跑每个渲染函数,**294 条断言**。断言的是**诚实性契约**:

- 不可测的指标必须在**它自己那一格**显示「不可测」,不能用 0 或 1.0 冒充
- 同名风险抽屉必须披露 Europe PMC 全库命中数与锚定计数
- 零锚定的 PI 必须给出「指纹请谨慎采信」告警
- 象限图必须报出被略过的位数并声明「没测到 ≠ 互补度为零」
- 排除名单必须真的列出高风险名字与原因
- 方法论页必须记录锚定反转、阈值改中位数、末位作者只是惯例这三条
- 每个筛选器都必须真的改变通过数(防止绑错 id 后静默失效)

**负控验证:** 手工注入 7 个退化(删掉每条披露、把两个不可测指标伪装成有值、
把高风险名字从排除名单里藏起来、让筛选器静默失效),**7 个全部被测出来**。
其中一个最初**没被测出来** —— 断言只查了卡片上有没有「不可测」三个字,
而隔壁那格恰好提供了这三个字;负控暴露后已改成定位到每个指标自己的单元格。

## 自动更新

`.github/workflows/update.yml` —— **每周一** 12:00 UTC。
PI 的方向指纹是多年尺度的量,天级刷新只会制造无意义的 diff。
流程:拉姊妹站最新语料(失败则沿用仓库里那份)→ 抓作品集 → 算指标 → 跑测试 → 有变化才提交。
